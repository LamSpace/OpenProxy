# Spec Delta

## Purpose

Defines the module-path identity of the published OpenProxy artifact and the
proxyability of targets that live in named JPMS modules, so that JPMS-native
deployments get a documented, diagnosable capability boundary.

## ADDED Requirements

### Requirement: Published jar declares a stable automatic module name

The published jar SHALL declare `Automatic-Module-Name: io.github.lamspace.openproxy`
in its manifest, so that when the jar is placed on the module path it resolves as the
automatic module `io.github.lamspace.openproxy` regardless of the jar's file name, and
a named module can `requires` it. The declaration SHALL have no effect on classpath
deployments: the set of class entries and all generated bytecode SHALL be identical to
the pre-change artifact.

#### Scenario: Module path discovery by declared name

- **WHEN** `ModuleFinder.of(openproxyJar)` resolves a jar whose file name is derived
  from any version string
- **THEN** the resulting module descriptor is an automatic module named
  `io.github.lamspace.openproxy`

#### Scenario: Classpath users see no change

- **WHEN** the same jar is loaded from the classpath
- **THEN** every proxy entry point behaves exactly as before
- **AND** no `module-info.class` is present in the artifact

### Requirement: Named-module targets are proxyable when the module requires the library

When the library and its ASM dependency are deployed on the module path and the
target's named module `requires` `io.github.lamspace.openproxy`, the system SHALL
proxy targets in that named module through the existing supplied-lookup entry points,
with the same placement, caching, and eviction semantics as any other supplied-lookup
call. The target module SHALL NOT need to export any package to the library.

#### Scenario: Class proxy inside a named module

- **WHEN** a public class in module `com.acme.proxyable` (which requires
  `io.github.lamspace.openproxy`; the target's own package is exported to no
  one) is proxied with a full-privilege lookup rooted in that module
- **THEN** the generated proxy class is defined in the module layer's loader and
  belongs to module `com.acme.proxyable`
- **AND** `invokeSuper` runs the target's real implementation
- **AND** the interceptor's return value is observable through a method call

#### Scenario: Supplied-lookup caching and eviction hold across the module boundary

- **WHEN** two proxies of the same named-module target are created from lookups rooted
  in the same class and later the module layer's loader is passed to
  `evictClassLoader`
- **THEN** the two proxies share one generated class before eviction
- **AND** after eviction plus GC the cache retains neither the lookup's root class nor
  the layer's loader

### Requirement: Supplied lookups instantiate with their own privilege

When a call supplies a definition lookup, the system SHALL create the proxy instance
using that lookup's privilege rather than cross-module reflection, so that targets in
named modules instantiate without the target package being exported or opened to the
library. Calls without a supplied lookup SHALL keep their existing instantiation
mechanism and behavior.

#### Scenario: Instantiation succeeds without any export

- **WHEN** a named-module target's package is exported to no one and the call supplies
  a full-privilege lookup rooted in that package
- **THEN** proxy construction completes without `IllegalAccessException`
- **AND** failures during construction still surface through the existing
  `Failed to create proxy` wrapping

### Requirement: Classpath deployment keeps the readability diagnostic

When the library is deployed from the classpath (its types in the unnamed module) and
the target lives in a named module, the system SHALL reject the call with an
`IllegalArgumentException` that names both modules, states that the target's module
must read the library's module, and presents the module-path remedy (place OpenProxy
and ASM on the module path and add `requires io.github.lamspace.openproxy;`). No
`IllegalAccessError` or other `LinkageError` SHALL escape class definition in this
shape.

#### Scenario: Diagnostic reports the module-path remedy

- **WHEN** a named-module target is proxied while the library sits on the classpath
- **THEN** the failure is an `IllegalArgumentException` naming the target's module and
  stating the readability requirement
- **AND** the message offers the module-path remedy instead of describing a permanent
  limitation of the library's packaging
